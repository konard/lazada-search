Title: Update Command Stream dependency range to remove the remaining braces advisory chain

Browser Commander 0.29.0 still depends on `command-stream: ^1.4.0`, which resolves to 1.6.2 and installs `shelljs@0.10.0 → fast-glob → micromatch → braces@3.0.3`. The advisory is GHSA-vfj7-8cjw-p6xm (nested-pattern stack-exhaustion DoS). Command Stream's existing issue https://github.com/link-foundation/command-stream/issues/221 is closed, and its current 2.0.2 registry package removes this dependency chain, but Browser Commander's 1.x range cannot select it.

An isolated Browser Commander 0.29.0 + Command Stream 2.0.2 installation audits with zero vulnerabilities, versus six highs in the equivalent 1.6.2 minimal tree. Our full project copied lock goes from five highs to zero using an exact scoped override. All seven Browser Commander subprocess contract fixtures pass against 1.6.2, 1.5.0 and 2.0.2: exact argv, stdin/environment, nonzero exit, output streaming, cancellation, missing executable and detached-child survival. The isolated contract pass did not access a browser or site. The integrated repository subsequently passed all35 browser/interface/native E2E cases, including actual local Chromium persistent-window recovery, login, capture, scroll, loading and CAPTCHA fixtures, without skips. Node 2.0.2's minimum >=22.0.0 is already covered by Browser Commander's >=22.12.0.

Please update the dependency to a tested 2.0.2-compatible range and run the project's complete browser-launch/capture fixture coverage, particularly its private ProcessRunner detach adapter. Consumers can temporarily apply `{ "overrides": { "browser-commander": { "command-stream": "2.0.2" } } }`. Browser Commander issues were checked before publishing; the prior broad audit report is #136, and the remaining1.x range in0.29.0 still prevents selecting the fixed2.x package. Raw registry/audit/TAP evidence is available from the accompanying public receipt.

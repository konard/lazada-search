## Original-page lifecycle

Detected browser challenges retain the exact CDP target and original origin through collector cleanup, capture/navigation timeouts, client restarts, graceful supervisor interruption and recovery. The first active challenge binding is persisted atomically across concurrent tabs. Pending CAPTCHA pages are exempt from ordinary 30-minute idle closure until guarded explicit resume or manual closure. After resume, ordinary inactivity closure applies again.

A missing or changed target remains stopped. Resume checks the retained target and origin and reconnects only that existing page; a clear sibling tab cannot clear its challenge. Failed supervisor recovery detaches without closing the original browser. Recovery/readiness/status metadata is published atomically, preventing partially written state from losing a live original target.

Library `collector.collectionStatus()`, CLI `collection-status`, Telegram `/collection_status` and HTTP `/api/collection-status` distinguish a durable stop from a confirmed visible handoff. Only an open headed original page is `awaiting-user`; headless, closed, unreachable and HTTP/archive-only sources have explicit separate states. Thirteen native retention regressions are included in the full E2E suite, with original document markers, exact target identities and unchanged navigation checked.

Its global stop remains active with accurate [`no-browser-page` status](saved-stop-status.json). No user-browser window was opened, reopened, navigated or closed to manufacture a waiting state. No challenge was bypassed, automatically cleared or resumed.
